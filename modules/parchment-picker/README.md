# Reusable parchment destination picker

This module is the presentation-only destination picker shared by wizard
guides and future carriage, boat, or other travel providers. It does not
charge the player, advance time, or move anyone.

Current status: native/Papyrus build and structural audits pass; the separate
wizard dialogue ESP is generated byte-idempotently. The core parchment flow is
gameplay-proven at 32:9 with external map-art dependencies. Boat providers
retain RUSTIC MAPS; wizard and carriage providers use Skyrim Paper Map by Caro
Tuts for FWMF and default to Norden UI symbols. The current
revision's multi-menu HUD suppression and ASCII footer are gameplay-proven.
The corrected original five-route star, crest centers, Winterhold origin, and
exact crop are visually gameplay-proven. Dawnstar and Morthal are added in the
current seven-route offline candidate and still need a visual alignment pass.
The stronger gold/red treatment and code-drawn Norden-style monochrome cursor
are also gameplay-proven. No-default-focus
startup, the translucent cursor center, and Escape cancellation are also
gameplay-proven. Mirabelle retains a dedicated matching subtitle. The first
actor-targeted voice experiment is rejected after crashing Skyrim through
CommonLibSSE-NG's stale `Script::CompileAndRun` relocation on 1.6.1170. The
current isolated candidate uses the official pinned CommonLib checkout but
bypasses that one convenience method with runtime-aware Address Library ID
`441582`. It accepts only Skyrim 1.6.1170 and offset `0x33D6A0`. The reusable
presentation contract additionally validates a live actor, constrained
installed FUZ path, subtitle, and measured duration. The corrected
playback itself is gameplay-proven. The follow-up timing candidate queues it
immediately from the Mirabelle INFO OnBegin fragment, pauses the silent owned
response, and suppresses the parchment map; all other faculty retain the proven
map path. That sequencing is also gameplay-proven. The current Candidate adds
the exact matching forced subtitle to Skyrim's normal `SubtitleManager` after
playback begins, using the manager's spin lock and Mirabelle's speaker handle.
Focused gameplay testing proved visible subtitle insertion alongside the voice
and lip sync. The current Candidate measures the exact XWM at 2.147846 seconds;
native code returns that duration plus a 0.20-second task margin before the
provider enters the normal parchment path. A rejected presentation falls back
to the map instead of denying travel. This generalized end-to-end handoff needs
one focused gameplay test; subtitle
lifetime/cleanup remains a minor regression check.

## Boundary

- Provider Papyrus supplies a request ID, source actor, artwork path, artwork
  aspect ratio, labels, fares, normalized marker positions, and an optional
  normalized route origin. It may also supply a validated speaker/FUZ/subtitle/
  measured-duration presentation before opening the picker.
- A provider may opt into one full-canvas transparent overlay texture. When it
  does, that texture supplies any permanent route marks. The beta boat and
  College presentations suppress all dynamic path strokes; boats use icon/halo
  state and the College uses the vanilla-map convention of modestly enlarging
  the currently focused destination icon. Other future providers may still use
  the retained route-graph renderer.
- A provider may call `SetMarkerTextures` before `Show` to select its own idle
  and highlighted marker artwork. Both paths are request data, must be supplied
  together, and are reloaded only when a later request changes theme. Requests
  that omit them retain the boat anchor/shipwreck defaults.
- After adding a destination, a provider may call
  `SetDestinationMarkerTexture` to override only that destination's neutral
  artwork. The request's highlighted texture remains shared, so a city can use
  its own castle while every selected wizard destination uses the same hat.
  Missing destination artwork falls back to the request's idle texture.
- Formal-map providers may call `SetSelectionRingScale` for the request-wide
  ring extent and `SetDestinationSelectionRingStyle` for an icon-specific X/Y
  optical offset and size multiplier. Offsets use rendered-icon half-extents,
  while the map coordinate, marker art, and interaction hitbox remain fixed.
  The companion calibrator exports the shared per-asset values from
  `config/icon-optics.json`; providers fan those values out to destinations
  that use the same marker texture.
- A provider may call `SetDestinationMarkerScale` after `AddDestination` to
  resize only that destination's rendered marker. The value multiplies the
  provider base size, is constrained to `0.5`-`2.0`, and does not alter the map
  anchor or interaction hitbox. Selection-ring offsets remain relative to the
  resulting rendered icon half-extent.
- A provider may call `SetOriginMarkerTexture` to give its route origin distinct
  artwork. If omitted or unavailable, the origin falls back to the selected
  marker texture, preserving existing boat-map behavior.
- A provider may add normalized `AddRouteSegment` edges. The picker draws the
  shared network once and computes the shortest origin-to-hovered-destination
  path for the red highlight when no painted overlay is present. Duplicate,
  zero-length, oversized, and disconnected graphs fail before the map is shown.
  Providers that omit these edges keep the original straight-spoke presentation.
- A provider whose terminal dialogue does not reliably dismiss itself may call
  `RequestDialogueClose`. The native runtime queues Skyrim's normal `kHide`
  message specifically for `Dialogue Menu`; it does not synthesize keyboard
  input or close unrelated menus.
- `DNTParchmentPicker.dll` presents those destinations in a blocking
  SKSE Menu Framework window.
- The picker returns only the selected zero-based index (or `-1` for cancel)
  over `DNT_ParchmentResult`.
- Provider Papyrus translates the index back to its stable destination ID.
- The existing provider service remains the only authority for validation,
  payment, time, and movement.

The interface deliberately avoids world-map references and BCD-specific data.
The proven BCD adapter remains untouched as a fallback and comparison point.

## Artwork dependency contract

No dependency map artwork is included in this module. `TexturePath` points to a
file installed by a separate dependency or a local development setup. The
picker logs `PARCHMENT_ART_MISSING` and leaves its destination buttons usable
when the file is absent, so an art dependency can never silently disable
travel. Optional provider overlays remain supported by the native interface,
but the beta package does not include or activate route artwork. The retained
authoring source can be revisited after release without changing the provider
or menu contracts.

Available ferry destinations use the project's stylized parchment anchor. Its
general design was AI-generated and then edited and touched up by the mod
author in Krita. The transparent 512-square source is encoded as
`textures/DiegeticTravel/docks-marker.dds`. The earlier Skyrim-derived
`DocksMarker` vector remains in the repository as a rollback source.

The active route uses the project's stylized parchment boat at both endpoints:
the current dock and the hovered destination. Its AI-assisted artwork was
supplied and edited by the mod author, then encoded as
`textures/DiegeticTravel/shipwreck-marker.dds`. The origin has no separate
ring, keeping the visual language to anchors for docks and boats for the active
journey. The earlier Skyrim-derived Shipwreck vector remains as a rollback
source. The previous code-drawn sailboat remains only as a safe fallback if an
icon texture cannot be loaded.

Inactive route landmarks use a stronger translucent gray anchor. Ferry maps
use the Lake Ilinalta-style beta presentation: no static chalk layer and no
dynamic path strokes. Hover state is communicated by the destination boat and
its subtle halo.

Wizard requests use the vanilla
`textures/DiegeticTravel/winterhold-college.dds` castle marker for the College
origin. Destinations use seven other hold-specific vanilla castle-marker
fallbacks exported from Skyrim's `interface/map.swf`, and retain their own
icon while highlighted; the red hover halo supplies the selection state.
Their SVG authoring sources, normalized PNGs, symbol IDs, and source hashes are
retained under `assets/vanilla-interface/hold-capitals/`. The former
Wheeler-derived marker remains only as a credited learning/rollback source and
is not bundled by the current build.

The current College path is:

```text
Data/textures/terrain/tamriel/skyrim.dds
```

`ArtAspectRatio` and the normalized UV crop rectangle are provider-owned.
Replacing an artwork dependency therefore requires coordinate/aspect/crop
configuration, not a native-code change.

The formal texture path, aspect, and crop are passed through local effective
values rather than the quest's auto-properties. This is intentional: an
existing save can retain the old battle-map property values even after a new
PEX is deployed.

The first local College proof used LoreRim's RUSTIC MAPS `battlemap01.dds`.
The current wizard candidate instead references the active 8192-square Caro
Tuts/FWMF texture and displays its illustration crop
`(0.088379,0.187012)-(0.932129,0.783691)` at aspect `1.414075`. Marker positions
are calculated from FWMF's exact Tamriel world-to-UV quad and the vanilla
map-marker reference coordinates rather than hand-tuned. The College origin
connects to Whiterun, Riften, Solitude, Windhelm, Markarth, Dawnstar, and
Morthal. Neither external map texture is copied into this module or archive.

## Dependencies

- SKSE
- Address Library through CommonLibSSE-NG
- SKSE Menu Framework 3 (LoreRim's installed file is labelled 3.9.0; its
  dynamic interface reported 3.7 in the successful runtime log)
- Loose external artwork dependencies at provider-configured paths (Caro Tuts
  for the current College and carriage providers; RUSTIC MAPS for boats)

Exact runtime hashes, the official CommonLib commit, vcpkg baseline, and the
`Script::CompileAndRun` relocation contract are pinned in
`dependencies.lock.json` and verified by
`tools/Audit-NativeDependencies.ps1` before the scripted native build.

The implementation dynamically resolves only framework functions that existed
in the v3 image/window interface. Missing functions disable the picker cleanly
and leave the existing dialogue destination menu available.

The generated wizard adapter deliberately does not master Better Carriage
Destinations. The proven BCD adapter remains a separate, unchanged fallback.

## Build and offline verification

```powershell
cmake --preset parchment-core
cmake --build --preset parchment-core
ctest --preset parchment-core

cmake --preset ae
cmake --build --preset parchment-ae
ctest --preset parchment-ae
```

The AE build copies the DLL and PDB only into this module's workspace `mod`
folder. It does not deploy to LoreRim. Papyrus compilation is handled by
`tools/Compile-ParchmentPickerPapyrus.ps1`.

Provider presentation IDs are compared ASCII case-insensitively at the native
boundary. This is required because live Papyrus requests may arrive as `Boat`
even when their source literal is `boat`; boat/College route suppression and
carriage marker sizing must not depend on that casing.
